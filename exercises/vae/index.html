    Enunciado

    Exercises → VAE

    Reprodutibilidade. Todos os números abaixo vêm de uma execução em CPU (PyTorch 2.14, torch.manual_seed(42) antes de construir cada modelo e Generator().manual_seed(42) no split). Os valores são determinísticos nessa configuração, mas outra máquina ou outra versão do PyTorch pode mudar as últimas casas decimais. Dependências: torch, torchvision, numpy, matplotlib, scipy, scikit-learn. O MNIST é baixado pelo torchvision para ~/.cache/ann-dl-mnist (fora do repositório; dá para trocar com a variável MNIST_DIR).

    Exercise 1

    A — Dados

    MNIST do torchvision, pixels em \([0,1]\) e imagens achatadas em vetores de 784 posições (dividir os bytes por 255 equivale ao ToTensor()). Os 60.000 exemplos de treino foram divididos com random_split e torch.Generator().manual_seed(42) em 50.000 para treino e 10.000 para validação; as 10.000 imagens oficiais de teste formam o conjunto de teste. O conjunto de teste só é usado nos números finais, e nenhuma decisão de treino o usa (não há early stopping nem seleção de modelo: são sempre 20 épocas e o modelo da última época é o avaliado).

    B — Modelo e loss

    Encoder \(784\to512\to256\) (ReLU), duas cabeças lineares \(256\to d\) para \(\mu\) e \(\log\sigma^2\), decoder \(d\to256\to512\to784\) (ReLU nas ocultas e sigmoide na saída), com \(d=16\). A loss por imagem, com \(\beta=1\), é

    \[ \mathcal L = \underbrace{-\sum_{j=1}^{784}\big[x_j\log\hat x_j+(1-x_j)\log(1-\hat x_j)\big]}_{\text{BCE}} \;+\;\beta\,\underbrace{\tfrac12\sum_{i=1}^{d}\big(\mu_i^2+\sigma_i^2-1-\log\sigma_i^2\big)}_{\text{KL}} \]
    • BCE. É o negativo do log da verossimilhança de Bernoulli, \(-\log p(x\mid z)\), o que combina com o MNIST (pixels quase binários, e a saída \(\hat x_j\) é uma probabilidade). Usei F.binary_cross_entropy(..., reduction="sum") e dividi pelo tamanho do batch; com reduction="mean" o termo de reconstrução ficaria dividido por 784 e o \(\beta\) efetivo seria ≈ 784.
    • KL em forma fechada. Para uma dimensão, com \(q=\mathcal N(\mu,\sigma^2)\) e \(p=\mathcal N(0,1)\): \(\mathrm{KL}=\mathbb E_q[\log q-\log p]=-\tfrac12\log\sigma^2-\tfrac12\frac{\mathbb E_q[(z-\mu)^2]}{\sigma^2}+\tfrac12\mathbb E_q[z^2]\), e como \(\mathbb E_q[(z-\mu)^2]=\sigma^2\) e \(\mathbb E_q[z^2]=\sigma^2+\mu^2\), resulta em \(\tfrac12(\mu^2+\sigma^2-1-\log\sigma^2)\). As \(d\) dimensões são independentes, então os KLs se somam. No código, \(\sigma^2=\exp(\text{logvar})\).
    • Reparametrização. \(z=\mu+\sigma\odot\varepsilon\) com \(\varepsilon\sim\mathcal N(0,I)\): o ruído é a única parte aleatória, então o gradiente passa por \(\mu\) e \(\sigma\).

    """
vae.py - VAE escrito do zero em PyTorch para o MNIST (Exercícios 1 e 2).

Escrito à mão (sem classes de VAE de bibliotecas e sem torch.distributions.kl_divergence):
  - a reparametrização z = mu + sigma * eps,
  - os dois termos da loss (BCE somada sobre os 784 pixels e KL em forma fechada),
  - a amostragem a partir do prior.
O autograd do PyTorch é usado só para os gradientes.

Unidades: todas as losses reportadas são em nats POR IMAGEM
(somadas sobre os 784 pixels / d dimensões latentes, médias sobre as imagens).
"""
import os
from pathlib import Path

import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import random_split
from torchvision import datasets

# O MNIST fica FORA do repositório (cache no diretório do usuário) para não ser commitado
# por engano. Dá para trocar o local com a variável de ambiente MNIST_DIR.
DATA_DIR = Path(os.environ.get("MNIST_DIR", Path.home() / ".cache" / "ann-dl-mnist"))
CKPT_DIR = DATA_DIR / "checkpoints"

BETA = 1.0
LR = 1e-3
BATCH_SIZE = 128
EPOCHS = 20


# ------------------------------------------------------------------- dados
def load_mnist():
    """
    Retorna (X_train, X_val, X_test, y_test) com X em [0,1], achatado em 784.

    Mesmo resultado que ToTensor() + flatten (ToTensor divide os bytes por 255).
    O split 50.000 / 10.000 usa random_split com Generator().manual_seed(42);
    o random_split só depende do tamanho do dataset, então os índices são os mesmos.
    """
    full = datasets.MNIST(DATA_DIR, train=True, download=True)
    test = datasets.MNIST(DATA_DIR, train=False, download=True)
    X_full = full.data.float().div(255.0).reshape(-1, 784)
    X_test = test.data.float().div(255.0).reshape(-1, 784)

    train_idx, val_idx = random_split(
        range(len(X_full)), [50_000, 10_000], generator=torch.Generator().manual_seed(42)
    )
    return X_full[list(train_idx)], X_full[list(val_idx)], X_test, test.targets


# ------------------------------------------------------------------ modelo
class VAE(nn.Module):
    """Encoder 784-512-256, cabeças mu / log sigma^2 (256 -> d), decoder d-256-512-784."""

    def __init__(self, d):
        super().__init__()
        self.d = d
        self.enc = nn.Sequential(
            nn.Linear(784, 512), nn.ReLU(),
            nn.Linear(512, 256), nn.ReLU(),
        )
        self.fc_mu = nn.Linear(256, d)
        self.fc_logvar = nn.Linear(256, d)
        self.dec = nn.Sequential(
            nn.Linear(d, 256), nn.ReLU(),
            nn.Linear(256, 512), nn.ReLU(),
            nn.Linear(512, 784), nn.Sigmoid(),   # probabilidade de cada pixel (Bernoulli)
        )

    def encode(self, x):
        h = self.enc(x)
        return self.fc_mu(h), self.fc_logvar(h)

    def reparameterize(self, mu, logvar, generator=None):
        """z = mu + sigma * eps, eps ~ N(0, I). O ruído eps é a única parte aleatória,
        então o gradiente passa por mu e sigma (truque da reparametrização)."""
        sigma = torch.exp(0.5 * logvar)
        eps = torch.randn(mu.shape, generator=generator)
        return mu + sigma * eps

    def decode(self, z):
        return self.dec(z)

    def forward(self, x, generator=None):
        mu, logvar = self.encode(x)
        z = self.reparameterize(mu, logvar, generator)
        return self.decode(z), mu, logvar


# -------------------------------------------------------------------- loss
def loss_terms(x_hat, x, mu, logvar):
    """
    Os dois termos da -ELBO, SOMADOS sobre o batch (dividir por N fora daqui).

    recon = -sum_j [ x_j log x_hat_j + (1 - x_j) log(1 - x_hat_j) ]     (BCE, reduction="sum")
    kl    = 1/2 sum_i ( mu_i^2 + sigma_i^2 - 1 - log sigma_i^2 )         (forma fechada
            de KL( N(mu, diag sigma^2) || N(0, I) ), com sigma^2 = exp(logvar))
    """
    recon = F.binary_cross_entropy(x_hat, x, reduction="sum")
    kl = 0.5 * torch.sum(mu.pow(2) + logvar.exp() - 1.0 - logvar)
    return recon, kl


@torch.no_grad()
def evaluate(model, X, seed=123, chunk=2000):
    """Reconstrução e KL médios por imagem (nats). A reconstrução usa UMA amostra de z por
    imagem (estimador de Monte Carlo da esperança), com gerador fixo para ser reprodutível."""
    model.eval()
    g = torch.Generator().manual_seed(seed)
    recon_sum, kl_sum = 0.0, 0.0
    for i in range(0, len(X), chunk):
        xb = X[i:i + chunk]
        x_hat, mu, logvar = model(xb, generator=g)
        r, k = loss_terms(x_hat, xb, mu, logvar)
        recon_sum += r.item()
        kl_sum += k.item()
    model.train()
    return recon_sum / len(X), kl_sum / len(X)


@torch.no_grad()
def kl_per_dim(model, X, chunk=2000):
    """KL média por imagem de cada dimensão latente (nats): mostra quais dimensões o modelo usa."""
    model.eval()
    total = torch.zeros(model.d)
    for i in range(0, len(X), chunk):
        mu, logvar = model.encode(X[i:i + chunk])
        total += 0.5 * (mu.pow(2) + logvar.exp() - 1.0 - logvar).sum(dim=0)
    model.train()
    return (total / len(X)).numpy()


@torch.no_grad()
def encode_mu(model, X, chunk=2000):
    """Média posterior mu de cada imagem (a codificação determinística)."""
    model.eval()
    out = torch.cat([model.encode(X[i:i + chunk])[0] for i in range(0, len(X), chunk)])
    model.train()
    return out


# ------------------------------------------------------------------ treino
def train_vae(d, X_train, X_val, epochs=EPOCHS, lr=LR, batch_size=BATCH_SIZE, beta=BETA,
              verbose=True):
    """
    Treina um VAE com Adam. Semente fixada ANTES de construir o modelo (torch.manual_seed(42)).
    No fim de cada época, mede reconstrução e KL (separados) no treino e na validação.
    Nenhuma decisão de treino usa o conjunto de teste (não há early stopping nem seleção).
    """
    torch.manual_seed(42)
    model = VAE(d)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    hist = {k: [] for k in ("train_recon", "train_kl", "val_recon", "val_kl")}

    n = len(X_train)
    for epoch in range(1, epochs + 1):
        perm = torch.randperm(n)  # embaralha a cada época (RNG global, já semeado)
        for i in range(0, n, batch_size):
            xb = X_train[perm[i:i + batch_size]]
            x_hat, mu, logvar = model(xb)
            recon, kl = loss_terms(x_hat, xb, mu, logvar)
            loss = (recon + beta * kl) / xb.shape[0]   # média sobre o batch, em nats/imagem
            opt.zero_grad()
            loss.backward()
            opt.step()

        tr_r, tr_k = evaluate(model, X_train)
        va_r, va_k = evaluate(model, X_val)
        for k, v in zip(hist, (tr_r, tr_k, va_r, va_k)):
            hist[k].append(v)
        if verbose:
            print(f"  [d={d}] época {epoch:2d}/{epochs}  train: recon={tr_r:7.2f} kl={tr_k:6.2f}"
                  f" | val: recon={va_r:7.2f} kl={va_k:6.2f}")
    return model, hist


def save_model(model, d):
    CKPT_DIR.mkdir(parents=True, exist_ok=True)
    torch.save(model.state_dict(), CKPT_DIR / f"vae_d{d}.pt")


def get_model(d, X_train, X_val):
    """Carrega o checkpoint de d, se existir; senão treina (determinístico, mesma semente)."""
    path = CKPT_DIR / f"vae_d{d}.pt"
    if path.exists():
        model = VAE(d)
        model.load_state_dict(torch.load(path))
        model.eval()
        return model
    model, _ = train_vae(d, X_train, X_val)
    save_model(model, d)
    return model


# --------------------------------------------------------------- utilidades
def images_to_grid(imgs, nrows, ncols):
    """(nrows*ncols, 784) -> imagem única (nrows*28, ncols*28), preenchida por linhas."""
    a = np.asarray(imgs).reshape(nrows, ncols, 28, 28)
    return a.transpose(0, 2, 1, 3).reshape(nrows * 28, ncols * 28)
    1. reparameterize e loss_terms são escritos à mão. Só o autograd é usado (para os gradientes).
    2. loss_terms devolve os dois termos somados no batch: dividir por \(N\) fora garante a unidade nats por imagem.

    C — Treino

    Adam, \(\eta=10^{-3}\), batch 128, 20 épocas, \(\beta=1\). Ao fim de cada época, reconstrução e KL são medidos separadamente no treino completo e na validação (nats por imagem; a reconstrução usa uma amostra de \(z\) por imagem, com gerador fixo).

    """
Exercise 1 - VAE no MNIST com espaço latente d = 16.
Treino, números de teste e Figuras 1, 2 e 3.
"""
import sys
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np
import torch

sys.path.insert(0, str(Path(__file__).resolve().parent))
import vae as V  # noqa: E402

FIGURES = Path(__file__).resolve().parents[1] / "figures"
D = 16


def main():
    FIGURES.mkdir(parents=True, exist_ok=True)
    X_train, X_val, X_test, y_test = V.load_mnist()
    print(f"treino={len(X_train)}  validação={len(X_val)}  teste={len(X_test)}")

    # --- C: treino ----------------------------------------------------------
    model, hist = V.train_vae(D, X_train, X_val)
    V.save_model(model, D)

    # números de teste: usados SÓ aqui, depois de o treino terminar
    te_r, te_k = V.evaluate(model, X_test)
    print(f"\n[C1] teste (d={D}): reconstrução = {te_r:.2f} nats, KL = {te_k:.2f} nats, "
          f"-ELBO = {te_r + te_k:.2f} nats")
    print(f"     validação KL: época 1 = {hist['val_kl'][0]:.2f}, época {V.EPOCHS} = {hist['val_kl'][-1]:.2f}")
    print(f"     validação recon: época 1 = {hist['val_recon'][0]:.2f}, época {V.EPOCHS} = {hist['val_recon'][-1]:.2f}")
    print(f"     treino -ELBO: época 1 = {hist['train_recon'][0] + hist['train_kl'][0]:.2f}, "
          f"época {V.EPOCHS} = {hist['train_recon'][-1] + hist['train_kl'][-1]:.2f}")
    kl_peak = int(np.argmax(hist["val_kl"])) + 1
    print(f"     KL de validação máxima na época {kl_peak}: {max(hist['val_kl']):.2f}")

    # dimensões latentes realmente usadas (KL média por dimensão, no teste)
    kd = V.kl_per_dim(model, X_test)
    print("\nKL por dimensão latente (teste, nats):", np.round(kd, 3))
    print(f"dimensões ativas (KL > 0.1 nat): {(kd > 0.1).sum()} de {D}")

    # --- Figura 1: curvas de treino -----------------------------------------
    epochs = np.arange(1, V.EPOCHS + 1)
    fig, axes = plt.subplots(1, 2, figsize=(11, 4.2))
    for ax, key, ylabel, title in [
        (axes[0], "recon", "Reconstrução (BCE, nats/imagem)", "Termo de reconstrução"),
        (axes[1], "kl", "KL (nats/imagem)", "Termo de KL"),
    ]:
        ax.plot(epochs, hist[f"train_{key}"], marker="o", markersize=3, label="Treino", color="#1f77b4")
        ax.plot(epochs, hist[f"val_{key}"], marker="s", markersize=3, label="Validação", color="#ff7f0e")
        ax.set_xlabel("Época")
        ax.set_xticks([1, 5, 10, 15, 20])
        ax.set_ylabel(ylabel)
        ax.set_title(title)
        ax.grid(alpha=0.3)
        ax.legend()
    fig.suptitle(f"Figura 1 - Termos da loss por época (VAE, d = {D})")
    fig.tight_layout()
    fig.savefig(FIGURES / "fig01-loss-terms.png", dpi=150)
    plt.close(fig)

    # --- Figura 2: reconstruções (decodificando mu, não um z amostrado) -------
    idx = [int((y_test == k).nonzero()[0]) for k in range(10)]
    print("\nprimeiro índice de teste de cada dígito 0-9:", idx)
    x = X_test[idx]
    with torch.no_grad():
        mu, _ = model.encode(x)
        rec = model.decode(mu)

    fig, axes = plt.subplots(2, 10, figsize=(13, 3.2))
    for k in range(10):
        axes[0, k].imshow(x[k].reshape(28, 28), cmap="gray")
        axes[1, k].imshow(rec[k].reshape(28, 28), cmap="gray")
        axes[0, k].set_title(f"dígito {k}", fontsize=9)
        for r in range(2):
            axes[r, k].set_xticks([])
            axes[r, k].set_yticks([])
    axes[0, 0].set_ylabel("Original", fontsize=10)
    axes[1, 0].set_ylabel("Recon.", fontsize=10)
    fig.suptitle("Figura 2 - Originais (topo) e reconstruções decodificando $\\mu$ (embaixo)")
    fig.tight_layout()
    fig.savefig(FIGURES / "fig02-reconstructions.png", dpi=150)
    plt.close(fig)

    # --- Figura 3: amostras do prior, grade 8x8 ------------------------------
    torch.manual_seed(0)
    z = torch.randn(64, D)
    with torch.no_grad():
        samples = model.decode(z)
    fig, ax = plt.subplots(figsize=(6, 6.4))
    ax.imshow(V.images_to_grid(samples.numpy(), 8, 8), cmap="gray")
    ax.set_xticks([])
    ax.set_yticks([])
    ax.set_xlabel("64 amostras independentes")
    ax.set_ylabel("Amostras")
    ax.set_title("Figura 3 - Amostras de $z \\sim \\mathcal{N}(0, I)$ decodificadas")
    fig.tight_layout()
    fig.savefig(FIGURES / "fig03-prior-samples.png", dpi=150)
    plt.close(fig)

    # evidência para a análise: a codificação agregada ocupa o prior?
    mu_test = V.encode_mu(model, X_test)
    print(f"\n||mu|| médio no teste = {mu_test.norm(dim=1).mean():.3f}   "
          f"(||z|| esperado sob o prior, d=16: ~{np.sqrt(D - 0.5):.3f})")
    print("média de mu por dimensão:", np.round(mu_test.mean(0).numpy(), 2))
    print("desvio de mu por dimensão:", np.round(mu_test.std(0).numpy(), 2))


if __name__ == "__main__":
    main()

    E — Análise

    1. Por que o otimizador aceita mais KL se a loss total cai? O que se minimiza é a soma dos dois termos, não cada um separadamente. O KL mede quanta informação sobre a imagem o encoder coloca em \(z\) (em nats), e é o "preço" dessa informação. No começo o código carrega pouca informação, e o decoder, sem saber qual dígito é, só consegue reconstruir uma imagem média. Cada nat extra de KL que o encoder "gasta" permite ao decoder cortar mais de um nat de reconstrução, então a soma diminui. Nos números: na validação, o KL sobe de 12.43 (época 1) para 19.63 (época 20; máximo de 19.73 na época 17) enquanto a reconstrução cai de 129.93 para 82.48, e a \(-\text{ELBO}\) de validação cai de 142.36 para 102.11. O KL só sobe enquanto cada nat adicional compra mais que um nat de reconstrução; nas épocas finais o ganho de reconstrução diminui e o KL se estabiliza em torno de 19–20 nats, que é o ponto onde os dois termos se equilibram. Um detalhe: das 16 dimensões latentes, 11 estão ativas e 5 ficaram com KL ≈ 0 no teste (≤ 0.002 nat, as dimensões de índice 4, 7, 9, 12 e 15, contando de 0), ou seja, o modelo "desligou" essas dimensões, porque não compensa pagar KL por elas.

    2. Por que a Figura 3 parece pior que a Figura 2? (Observação: a Figura 2 também não é perfeita: as reconstruções do 3, do 5 e do 8 saem borradas ou trocadas, o 3 vira algo parecido com um 8 e o 8 vira uma mancha. Mesmo assim os traços de Fig. 2 são mais nítidos que os da Fig. 3.) Duas razões distintas:

    • Onde as amostras do prior caem no espaço latente. O decoder só foi treinado em pontos \(z\) vindos do encoder, ou seja, da distribuição agregada \(q(z)=\frac1N\sum_x q(z\mid x)\). O KL aproxima cada \(q(z\mid x)\) do prior só em média, então \(q(z)\) não preenche o prior por inteiro: os dígitos formam regiões, e é plausível que entre elas fiquem zonas onde o prior tem massa, mas o decoder viu poucos dados (a Figura 4, no caso \(d=2\), mostra a distribuição agregada organizada em aglomerados por dígito, com zonas de transição entre eles). Uma amostra \(z\sim\mathcal N(0,I)\) que cai num buraco ou numa fronteira entre classes decodifica para algo ambíguo ou híbrido (várias amostras da Figura 3 não são dígitos reconhecíveis). Na Figura 2, ao contrário, o \(z\) vem do encoder e cai numa região bem treinada.
    • O que o decoder devolve para um dado \(z\). O decoder produz as probabilidades \(\hat x_j=p(x_j=1\mid z)\) de cada pixel (saída sigmoide com verossimilhança de Bernoulli), isto é, a média condicional \(\mathbb E[x\mid z]\), e não uma imagem sorteada. Um \(z\) de 16 números (e com o KL limitando a informação) não fixa detalhes como a espessura exata ou a posição fina do traço, então o decoder responde com a média das imagens compatíveis com aquele \(z\), que é uma imagem de traços suaves e borrados. Na Figura 2 o \(z\) é informativo sobre aquela imagem específica, então a média fica próxima do original; na Figura 3, \(z\) não tem uma imagem de origem, e o que sai é só a média borrada.

    3. Por que decodificar \(\mu\) e não um \(z\) amostrado na Figura 2? A Figura 2 quer mostrar quanto da imagem o código preserva. \(\mu\) é a média da posterior, o ponto central e determinístico da crença do encoder. Decodificar um \(z=\mu+\sigma\varepsilon\) misturaria a qualidade da reconstrução com o ruído de amostragem: a mesma imagem produziria reconstruções diferentes a cada execução, com parte do erro vindo do sorteio e não do modelo. Com \(\mu\), a figura é reprodutível e mostra a melhor estimativa do encoder.

Exercise 2 - espaço latente 2-D: mesmo modelo, dados, semente, beta e orçamento, com d = 2.

import sys
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np
import torch
from scipy.stats import norm
from sklearn.metrics import confusion_matrix
from sklearn.neighbors import KNeighborsClassifier

sys.path.insert(0, str(Path(__file__).resolve().parent))
import vae as V  # noqa: E402

FIGURES = Path(__file__).resolve().parents[1] / "figures"


def main():
    FIGURES.mkdir(parents=True, exist_ok=True)
    X_train, X_val, X_test, y_test = V.load_mnist()

    # --- A: modelo d = 2 (mesmo orçamento do d = 16) -------------------------
    model2, hist2 = V.train_vae(2, X_train, X_val)
    V.save_model(model2, 2)
    model16 = V.get_model(16, X_train, X_val)   # o mesmo modelo do Exercício 1

    r2, k2 = V.evaluate(model2, X_test)
    r16, k16 = V.evaluate(model16, X_test)
    print(f"\n[A] teste d= 2: reconstrução = {r2:.2f}, KL = {k2:.2f}, -ELBO = {r2 + k2:.2f} nats")
    print(f"    teste d=16: reconstrução = {r16:.2f}, KL = {k16:.2f}, -ELBO = {r16 + k16:.2f} nats")
    print(f"    KL por dimensão (d=2, teste): {np.round(V.kl_per_dim(model2, X_test), 3)}")

    # --- B: Figura 4 - mu de todo o teste, colorido por dígito ----------------
    mu = V.encode_mu(model2, X_test).numpy()
    y = y_test.numpy()
    fig, ax = plt.subplots(figsize=(7.5, 6.5))
    cmap = plt.get_cmap("tab10")
    for k in range(10):
        ax.scatter(mu[y == k, 0], mu[y == k, 1], s=5, alpha=0.6, color=cmap(k), label=str(k))
    ax.set_xlabel("$\\mu_1$")
    ax.set_ylabel("$\\mu_2$")
    ax.set_title("Figura 4 - Média posterior $\\mu$ das 10.000 imagens de teste (d = 2)")
    ax.legend(title="Dígito", markerscale=3, loc="center left", bbox_to_anchor=(1.0, 0.5))
    ax.grid(alpha=0.3)
    fig.tight_layout()
    fig.savefig(FIGURES / "fig04-latent-scatter.png", dpi=150)
    plt.close(fig)

    # evidência numérica da sobreposição: kNN em 2-D (ajustado em mu do treino, avaliado no teste)
    mu_train = V.encode_mu(model2, X_train).numpy()
    # rótulos do treino: refaz o mesmo split para obter y de treino
    from torchvision import datasets
    from torch.utils.data import random_split
    y_full = datasets.MNIST(V.DATA_DIR, train=True, download=True).targets
    tr_idx, _ = random_split(range(60000), [50_000, 10_000], generator=torch.Generator().manual_seed(42))
    y_train = y_full[list(tr_idx)].numpy()
    knn = KNeighborsClassifier(n_neighbors=15).fit(mu_train, y_train)
    pred = knn.predict(mu)
    cm = confusion_matrix(y, pred)
    print(f"\n[E] kNN (k=15) sobre mu em 2-D: acurácia de teste = {(pred == y).mean():.4f}")
    pairs = []
    for i in range(10):
        for j in range(i + 1, 10):
            pairs.append((cm[i, j] + cm[j, i], i, j))
    pairs.sort(reverse=True)
    print("    pares de dígitos mais confundidos em 2-D (erros nos dois sentidos):")
    for n, i, j in pairs[:6]:
        print(f"      {i} e {j}: {n}")
    rec_digit = cm.diagonal() / cm.sum(axis=1)
    print("    recall por dígito:", {k: round(float(r), 3) for k, r in enumerate(rec_digit)})
    print("    centroide de mu por dígito:",
          {k: tuple(np.round(mu[y == k].mean(0), 2)) for k in range(10)})
    print(f"    faixa de mu: x=[{mu[:, 0].min():.2f}, {mu[:, 0].max():.2f}]  "
          f"y=[{mu[:, 1].min():.2f}, {mu[:, 1].max():.2f}]")

    # --- C: Figura 5 - grade 15x15 decodificada, espaçada por Phi^-1 ----------
    n = 15
    q = np.linspace(0.05, 0.95, n)
    zs = norm.ppf(q)                      # z = Phi^{-1}(q): cada célula tem a mesma massa no prior
    print(f"\n[C] z na grade (Phi^-1 de q em [0.05, 0.95]): {np.round(zs, 3)}")
    # linha de cima = maior z2, para o eixo vertical crescer para cima (como na Figura 4)
    grid = np.array([[zx, zy] for zy in zs[::-1] for zx in zs], dtype=np.float32)
    with torch.no_grad():
        imgs = model2.decode(torch.from_numpy(grid)).numpy()
    canvas = V.images_to_grid(imgs, n, n)

    fig, ax = plt.subplots(figsize=(8, 8))
    ax.imshow(canvas, cmap="gray", extent=(0, n * 28, n * 28, 0))
    ticks = [28 * i + 14 for i in (0, 3, 7, 11, 14)]
    ax.set_xticks(ticks, [f"{zs[i]:.2f}" for i in (0, 3, 7, 11, 14)])
    ax.set_yticks(ticks, [f"{zs[::-1][i]:.2f}" for i in (0, 3, 7, 11, 14)])
    ax.set_xlabel("$z_1 = \\Phi^{-1}(q_1)$")
    ax.set_ylabel("$z_2 = \\Phi^{-1}(q_2)$")
    ax.set_title("Figura 5 - Plano latente 2-D decodificado (grade 15×15, $q \\in [0.05, 0.95]$)")
    fig.tight_layout()
    fig.savefig(FIGURES / "fig05-latent-grid.png", dpi=150)
    plt.close(fig)

    # --- D: Figura 6 - interpolação pixel vs. latente (modelo d = 16) ---------
    # Escolha (regra fixa, antes de ver o resultado): primeira imagem de teste dos dígitos 3 e 7.
    ia = int((y_test == 3).nonzero()[0])
    ib = int((y_test == 7).nonzero()[0])
    print(f"\n[D] índices de teste interpolados: {ia} (dígito {int(y_test[ia])}) e "
          f"{ib} (dígito {int(y_test[ib])})")
    xa, xb = X_test[ia], X_test[ib]
    ts = torch.linspace(0, 1, 10)
    pixel_row = torch.stack([(1 - t) * xa + t * xb for t in ts])
    with torch.no_grad():
        mu_a, _ = model16.encode(xa[None])
        mu_b, _ = model16.encode(xb[None])
        latent_row = model16.decode(torch.cat([(1 - t) * mu_a + t * mu_b for t in ts]))

    fig, axes = plt.subplots(2, 10, figsize=(13, 3.4))
    for k, t in enumerate(ts):
        axes[0, k].imshow(pixel_row[k].reshape(28, 28), cmap="gray")
        axes[1, k].imshow(latent_row[k].reshape(28, 28), cmap="gray")
        axes[0, k].set_title(f"t = {t:.2f}", fontsize=9)
        for r in range(2):
            axes[r, k].set_xticks([])
            axes[r, k].set_yticks([])
    axes[0, 0].set_ylabel("Pixels", fontsize=10)
    axes[1, 0].set_ylabel("Latente", fontsize=10)
    fig.suptitle(f"Figura 6 - Interpolação entre as imagens de teste {ia} (dígito 3) e {ib} (dígito 7): "
                 "pixels (topo) vs. latente d = 16 (embaixo)")
    fig.tight_layout()
    fig.savefig(FIGURES / "fig06-interpolation.png", dpi=150)
    plt.close(fig)

    E — Análise

    1. Quais dígitos se sobrepõem na Figura 4, e a mesma transição na Figura 5. Na Figura 4, os dígitos 0 (à esquerda), 1 (à direita), 7 (em cima) e 3 (embaixo) ocupam regiões bem separadas, enquanto 2, 4, 5, 8 e 9 se amontoam no centro. Para quantificar, ajustei um kNN (k = 15) sobre os \(\mu\) 2-D do treino e o avaliei no teste: acerta só 79.4%, e os pares mais confundidos (erros nos dois sentidos) são 4 e 9 (596 erros), 3 e 5 (328), 7 e 9 (163), 5 e 8 (159) e 3 e 8 (156); o recall do 5 é 52.2%, o do 4 é 61.6% e o do 9 é 61.8%, contra 96.6% do 0 e 97.9% do 1. Na Figura 5, a transição 4 ↔ 9 aparece na região superior central: indo da esquerda para a direita nas linhas de \(z_2\approx0.5\) a \(1.2\), vem uma sequência de 4 e depois de 9, e as células de transição são híbridos, com o topo parcialmente aberto, entre um 4 e um 9 (traços mais fracos e borrados). A fronteira 3 ↔ 5 aparece na parte de baixo, com 5 e 3 alternados e imagens ambíguas entre eles, e há uma zona de transição 6/2/4 no centro, de traços sobrepostos e quase ilegíveis. Nenhuma fronteira é abrupta: as classes se misturam continuamente, o que casa com a sobreposição vista na Figura 4.

    2. O que dois números por imagem obrigam o modelo a descartar. Com \(d=2\) a reconstrução é 135.54 nats, contra 81.88 com \(d=16\) (+53.7 nats). Dois números precisam codificar qual dígito e todo o resto, então o modelo guarda a identidade grosseira do dígito e uma pequena variação de estilo (inclinação, largura geral) e descarta os detalhes do traço: a espessura, a forma exata das curvas, os laços e as pequenas variações de caligrafia. A Figura 5 mostra isso: dentro de cada região, todas as células mostram um protótipo do dígito (os 0 são todos iguais, os 1 são linhas finas que só variam de inclinação ao longo da borda direita), e as imagens são mais borradas que as reconstruções com \(d=16\). Esse protótipo é o que sobra quando só há duas coordenadas: todas as imagens de um mesmo dígito com pequenas diferenças de estilo são mapeadas para o mesmo ponto.

    3. Comparação das duas linhas da Figura 6. A linha de pixels é uma superposição: em \(t=0.5\) aparece o 3 e o 7 ao mesmo tempo, cada um com metade da intensidade, e nenhum quadro intermediário parece um dígito. A linha latente faz uma transição contínua: o traço do 3 vai se transformando na curva de cima do 7 (passando por formas curvas e uma haste), e os quadros a partir de \(t\approx0.55\) já parecem 7 de verdade. Os quadros do meio (\(t\approx0.33\)–\(0.44\)) são formas curvas borradas, que lembram pouco um dígito, então a interpolação latente também não é perfeita. A razão da diferença: as imagens que parecem dígitos ocupam uma superfície fina e curva dentro do espaço de 784 pixels, e a reta entre duas imagens no espaço de pixels sai dessa superfície (mistura de dois dígitos não é um dígito). No espaço latente, o decoder aprendeu a mapear as vizinhanças dos códigos (e o KL aproxima os códigos do prior e os faz se sobreporem), então a reta entre dois \(\mu\) passa por códigos que o decoder mapeia para imagens plausíveis. Uma ressalva: no quadro \(t=0\) da linha latente o 3 não aparece como o original, porque é a reconstrução do modelo \(d=16\) para essa imagem, que parece um 8 (é a mesma imagem 3 que a Figura 2 mostra reconstruída como um 8).

    Discussão

    Quatro pontos de transparência. (1) A reconstrução de teste usa uma única amostra de \(z\) por imagem (estimador de Monte Carlo); com 10.000 imagens o ruído é pequeno, mas não nulo, e o KL é calculado em forma fechada e portanto exato. (2) Nada foi ajustado olhando o teste: arquitetura, \(\eta\), batch, épocas e \(\beta\) são os do enunciado. (3) As afirmações sobre "buracos" no espaço latente do modelo \(d=16\) (item 1E.2) são uma interpretação apoiada na Figura 4 do modelo \(d=2\) e no aspecto das amostras da Figura 3, e não uma medição direta da densidade agregada em 16 dimensões. (4) O par de imagens da interpolação foi escolhido por uma regra simples (primeira imagem de cada dígito), não por ser o mais bonito: a linha latente tem quadros intermediários borrados, e isso está no texto.
